The assessment in context

A public demonstration of practical API security testing and CORS origin validation.

How well does your business protect its APIs against unauthorised access?

Today, I carried out an authorised API security assessment of my own business website using Burp Suite.

One of the tests focused on CORS (Cross-Origin Resource Sharing), which controls which website origins are permitted to make browser-based cross-origin requests.

What did I do?

  • Captured live API traffic using Burp Suite.
  • Examined HTTP requests and responses.
  • Simulated a request from an untrusted origin.
  • Inspected the backend response and CORS headers.
  • Checked whether the untrusted origin was accepted or rejected.

The result: the request from an untrusted origin received HTTP 403 Forbidden. The backend also returned “Origin not allowed.” This is positive evidence that the tested origin restriction was working as expected.

1. Burp Suite request evidence

The test used an OPTIONS preflight request with an untrusted origin value.

Burp Repeater - RequestCORS preflight test
RequestOPTIONS /functions/v1/zee-ai-demo HTTP/2 Host: PROJECT-HOST Origin: https://example.com Access-Control-Request-Method: POST Access-Control-Request-Headers: content-type,x-client-info Sec-Fetch-Site: cross-site Sec-Fetch-Mode: cors Sec-Fetch-Dest: empty Content-Length: 71
Test objectiveSend a browser-style preflight request from an origin that should not be authorised. Check whether the API: - rejects the origin - exposes a permitted origin - permits the requested method and headers - returns an appropriate HTTP status

2. Backend response evidence

The untrusted origin was rejected by the server.

Burp Repeater - ResponseHTTP 403 result
ResponseHTTP/2 403 Forbidden Date: REDACTED Content-Type: text/plain; charset=UTF-8 X-Deno-Execution-Id: REDACTED Strict-Transport-Security: max-age=31536000 Server: REDACTED Origin not allowed
InterpretationThe backend returned HTTP 403 Forbidden for the tested origin. This provides positive evidence that origin restrictions were enforced for this controlled request. It is one focused control check, not proof that every endpoint or browser workflow is secure.

3. What was demonstrated

The evidence is translated into a clear testing outcome and next step.

Technical work performed

  • Captured live API traffic using Burp Suite.
  • Examined HTTP requests and responses.
  • Simulated a request from an untrusted origin.
  • Inspected the backend response and CORS headers.
  • Checked whether the unauthorised origin was accepted or rejected.

Outcome and relevance

The tested origin received HTTP 403 Forbidden with the response “Origin not allowed.” This shows that the tested CORS restriction worked as expected.

CORS misconfiguration can allow unintended websites to make browser-based API requests. API security testing helps identify when authentication, authorisation or origin controls require review.

Demonstration status: This is a controlled technical example using redacted identifiers. It is not presented as a completed customer penetration test or a guarantee of application security.
